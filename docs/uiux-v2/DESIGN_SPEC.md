# JISUMAN LLM Benchmark GUI — 统一设计规范 v2

适用范围：`/opt/llm-benchmark`（Tkinter 桌面客户端）
本文档是**唯一权威规范**，代码侧令牌权威实现在 `llm_benchmark_app/ui_theme.py`。
二者冲突时以 `ui_theme.py` 为准，并同步修改本文档。

定位：**企业级大模型性能基准测试与客户验收工具**（不是模型切换控制台）。
视觉方向：克制、清晰、可信的国际企业软件；让关键数字与异常先被看见。

参考对象：Grafana（信息呈现：面板化、状态色语义化、单位明确、时间与范围可见）、
NVIDIA GenAI-Perf / NIM（指标组织：吞吐/延迟/可靠性三类、单请求 vs 系统级口径分离）。
品牌保留：极算门 JISUMEN 品牌蓝 `#0060F0` 与官方字标，不重绘、只机械裁切。

---

## 1. 设计原则（冲突时的仲裁顺序）

1. **数字优先**：任何页面在 3 秒内应能回答「现在跑得怎么样 / 上一轮什么水平 / 有什么异常」。
2. **口径显式**：每个数字都带单位与口径；单请求口径与系统口径绝不混排在同一组。
3. **差异必标注**：不同配置/口径的数据放在一起时，必须显式标注差异，禁止呈现为同条件对比。
4. **诚实呈现**：未接入/未测量标「待接入」「未测」；演示数据必须带可见标注。
5. **一致性**：同一指标跨页面/跨 Tab 同口径、同格式、同颜色语义（颜色不是装饰）。
6. **克制**：颜色只用于语义与系列区分，不做彩虹装饰；无 emoji 当图标。

### 2.1 中性面（surface）

| 令牌 | 亮色值 | 用途 |
|---|---|---|
| `bg_main` | `#F4F6FA` | 应用底、页面背景 |
| `bg_card` | `#FFFFFF` | 卡片/面板面 |
| `bg_header` | `#FFFFFF` | 顶栏、工具栏 |
| `bg_inset` | `#F1F5F9` | 表头、嵌入区（比卡片低一层） |
| `bg_hover` | `#EEF2F8` | 行悬停、按钮悬停 |
| `bg_stripe` | `#F8FAFD` | 斑马纹行 |
| `border` | `#DCE3EC` | 卡片描边、表格线 |
| `border_light` | `#EDF1F6` | 组内分隔线 |
| `border_strong` | `#C3CDDB` | 输入框描边、需要在底色上被看见的边 |
| `border_focus` | `#0060F0` | 键盘焦点环 |

### 2.2 文字

| 令牌 | 值 | 白底对比度 | 用途 |
|---|---|---|---|
| `text_primary` | `#0F172A` | 17.9:1 | 正文、数值主色 |
| `text_secondary` | `#475569` | 7.5:1 | 次级文字、标签 |
| `text_muted` | `#64748B` | 4.8:1 | 提示、单位（仍须 ≥4.5） |
| `text_inverse` | `#FFFFFF` | — | 实心按钮上的文字 |
| `text_disabled` | `#94A3B8` | 2.6:1 | **仅**禁用态（不承载信息） |

### 2.3 品牌与语义

| 令牌 | 值 | 语义（唯一含义） |
|---|---|---|
| `accent` / `accent_hover` / `accent_pressed` | `#0060F0` / `#0052CF` / `#003FA8` | 品牌蓝：主操作、当前选中、焦点 |
| `accent_light` / `accent_soft` | `#E8F0FE` / `#D3E4FD` | 品牌蓝浅底（选中行、当前项） |
| `success` / `success_bg` / `success_text` | `#2FAF63` / `#E9F7EF` / `#146C3B` | 成功、通过、连接正常 |
| `warning` / `warning_bg` / `warning_text` | `#D29922` / `#FDF6E7` / `#8A5A00` | 需注意、有失败但可接受、口径不一致 |
| `error` / `error_bg` / `error_text` | `#E5534B` / `#FDECEB` / `#B3261E` | 失败、错误、不可用 |
| `info` / `info_bg` / `info_text` | `#4A9EDA` / `#EAF4FB` / `#0B5FA5` | 中性提示、说明 |
| `neutral` / `neutral_bg` | `#8A92A1` / `#F1F3F6` | 未测量、未接入、空值 |

**禁用规则**：失败率、错误计数以外的数字**不得**用红色/绿色；指标卡默认中性色，
只有该数值的**语义**确实为好/坏时才着色（例如成功率 <100% 才转警告色）。

### 2.4 数据可视化色板（仅用于图表系列 identity）

`#0060F0`（蓝）· `#14B8A6`（青）· `#D97706`（琥珀）· `#7C3AED`（紫）· `#64748B`（灰=基线）

- 图表必须有**直接标签或图例**，不得仅靠颜色区分系列；
- 单位写在轴标题或图例里（`tokens/s`、`ms`、`req/s`）；
- 空数据画布显示「暂无数据」文案，不画空白网格。

### 2.5 间距（4/8 节奏）

`xs=4 · sm=8 · md=12 · lg=16 · xl=24 · 2xl=32`；卡片内边距 16，卡片间距 12，页面外边距 24。

### 2.6 字号与字体

UI 家族：`Noto Sans CJK SC`（Linux）/ `Microsoft YaHei UI`（Windows）/ `PingFang SC`（macOS）；
数值家族（等宽、字宽对齐）：`Noto Sans Mono CJK SC` / `Consolas` / `Menlo`。

| 令牌 | 字号/字重 | 用途 |
|---|---|---|
| `display` | 26 bold | 总览页首页大数字（仅 1–2 处） |
| `metric_lg` | 20 bold | 结果指标卡主数值 |
| `metric_md` | 15 bold | 表内数值、次级指标 |
| `section` | 13 bold | 卡片标题 |
| `body` | 12 | 正文 |
| `label` | 12 | 表单标签 |
| `meta` | 11 | 单位、口径、时间戳 |
| `caption` | 10 | 脚注、证据路径 |

数值一律**右对齐或等宽对齐**，百分比 1 位小数，毫秒整数或 3 位有效数字。

## 3. 组件规范

### 3.1 卡片 `SectionCard`
白底 + 1px `border` + 圆角 8 + 内边距 16；标题行：`section` 字号 + 可选副标题（`meta`）+ 右侧操作区。
折叠用卡片头部整行可点（含 `▸/▾` 指示），不用独立按钮；**折叠态不得丢失关键数字**。

### 3.2 指标卡 `MetricTile`
结构固定：`标签 → 数值(+单位) → 口径/备注`。默认中性色；`tone` 只允许 `neutral|success|warning|error|accent`。
空值显示 `—` 并配 `meta` 说明原因（如「未开始」），不显示 0。
**分组**：延迟类（TTFT/TPOT/ITL/E2E）、吞吐类（Output TPS / Total TPS / RPS）、可靠性（成功率/失败数）。
分组标题必须写明口径：`单请求（per-request）` / `系统级（system）`。

### 3.3 状态徽标 `StatusBadge`
`成功/失败/进行中/待运行/未接入` 五种，颜色取自语义令牌，文字同时表达状态（不靠颜色单独表意）。

### 3.4 表格
- 行高 26（密集模式 24），斑马纹 `bg_stripe`，表头 `bg_inset` + `text_secondary`；
- 数值列右对齐、等宽字体；单位写在表头（`TTFT (ms)`）而非每行；
- 列宽：先给语义优先级（关键列宽、次要列窄），不允许出现被截断到不可读的列（如 `Backer`）；
- 选中行：`accent_light` 底 + 左侧 3px 品牌蓝条；
- 排序：表头显示 `▲/▼`，默认按时间倒序；筛选控件紧邻表格，显示当前生效筛选；
- 空态：表格区域替换为 `EmptyState`，不是空白表格。

### 3.5 按钮层级
- `primary`：品牌蓝实心，同屏最多 1 个；
- `secondary`：白底 + `border_strong` 描边；
- `ghost`：无描边，悬停才出底色（用于表格行内操作）；
- `danger`：仅用于破坏性操作（清空记录），红色描边，不做实心大红。
按钮高度 32（文中）/ 36（主操作），最小点击区 32×32。

### 3.6 空态 `EmptyState`
三行：**发生了什么**（如「还没有测试记录」）→ **为什么/能得到什么** → **主操作按钮**。
空态禁止只显示 `—`、`暂无数据` 而无下一步动作。

### 3.7 进度与进行中
必须同时呈现：当前阶段（步进器）、已完成/总数、成功/失败、已用时、实时吞吐、
当前并发档（扫测时按档位列出已完成档）、**失败原因入口**（可点开看错误分类与样例）。
长任务必须有「取消」；取消后状态回到「已取消」而不是「失败」。

### 3.8 口径与证据
每个结果详情/报告顶部固定一块 **运行证据（Run Provenance）**：时间、工具版本、git 提交、
API 端点、模型、环境档案（硬件/软件栈/模型档案快照）、并发、请求数、输入/输出长度、
温度、流式、预热次数、测试时长、指标口径版本。缺失字段显示「未记录」而不是留空。

## 4. 页面规范

| 页面 | 职责 | 关键要求 |
|---|---|---|
| **总览** | 3 秒看懂现状 | 最近一轮关键数字（TTFT/Output TPS/成功率）、当前配置与环境摘要、最近趋势、待处理事项（失败/口径异常/未接入）、三个入口：新建测试 / 继续上次配置 / 最近报告 |
| **新建测试** | 配置与预检 | 单列卡片流：目标（单请求速度 / 峰值吞吐扫描）→ 端点与模型 → 工作负载（并发/请求数/输入输出长度/温度/流式/预热）→ 预检摘要（连通性、模型、预估请求数、预计耗时）→ 主操作「开始测试」 |
| **测试进行中** | 实时可见 | 步进器 + 实时指标 + 失败原因；不遮挡内容（禁止全屏遮罩挡掉进展信息） |
| **结果详情** | 可验收 | 指标分组（延迟/吞吐/可靠性）+ 分布图 + 每请求明细 + 证据块 + 导出入口；失败请求可按错误分类过滤查看原因 |
| **历史对比** | 比较两次运行 | 选择 A/B → 参数差异表（模型/框架/并发/输入输出/温度/流式/口径差异）→ 指标并排 + 差值；**参数或口径不同必须打「不可直接比较」警示并列出差异项** |
| **报告与证据** | 交付 | 选择运行 → 交付件清单（report.txt/md、charts、result.json、summary.json、manifest、DOCX/PDF）→ 导出目录/打包 → 打开所在目录；导出前显示包含内容与生成时间 |
| **环境档案** | 环境事实来源 | 保留既有硬件/软件栈/模型/档案/数据库五页，视觉对齐（=「SystemHealth」等价物，不重做结构） |

## 5. 交互与可访问性

- **键盘**：`Tab` 顺序与视觉顺序一致；`Ctrl+1..7` 切页；`Enter` 触发主操作；
  `Esc` 关闭对话框；`F5` 刷新历史；可见焦点环（2px 品牌蓝）。所有仅鼠标可用的操作必须有键盘等价。
- **对比度**：文字 ≥4.5:1，非文字（边框、图标、图表线）≥3:1；验收方式见 `scripts/uiux_contrast_audit.py`。
- **窗口**：可缩放且布局随之自适应；在 1366×768 / 1600×900 / 1920×1080 上均无横向截断与重叠。
- **状态反馈**：任何异步操作 ≤200ms 内有反馈（按钮禁用 + 进度或文案）；失败必须给出原因与下一步。

## 6. 演示数据标注规则

- 使用本地 mock 端点（`scripts/demo_mock_openai_server.py`）产生的数据属于**演示数据**；
- 演示数据在以下位置必须可见标注：总览页顶部横幅、结果详情证据块「数据来源」字段、
  历史列表行内徽标、导出报告首页页脚；
- 标注文案固定：`演示数据（本地 mock 端点，非真实硬件/模型性能）`；
- 真实跑测数据不得出现该标注；判定依据记录在 `summary.json` 的 `data_source` 字段。
